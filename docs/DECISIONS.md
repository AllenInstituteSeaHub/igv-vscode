# Decisions

Choices not covered by the design spec, with reasons (spec §0 item 4).

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-10-03 | TypeScript 5.9 rather than 7.x | TS 7 is the native (Go) compiler preview; tooling (typescript-eslint, vitest) targets 5.x. Revisit when 7 is mainstream. |
| 2 | 2026-10-03 | `@types/node` 22 with esbuild `target: node18` | `@types/node` 18 conflicts with vitest 5 / vite 8 peer ranges. We avoid APIs newer than Node 18 in host code; VS Code 1.85 ships Node 18, current builds ship Node 22. |
| 3 | 2026-10-03 | Shared host/webview modules in `src/shared/` | `Rpc` and the host↔webview message types are needed by both bundles. `webview/rpc.ts` re-exports so the spec's file name still exists. |
| 4 | 2026-10-03 | Webview bundle output at `dist/webview.js`; `localResourceRoots` = `[media, dist]` | Keeps all build output under `dist/`. `media/` stays for vendored and static assets. |
| 5 | 2026-10-03 | igv loaded as the UMD global via `<script>` rather than bundled by esbuild | Matches the spec's `scripts/copy-igv.mjs` and lets the contract test load the exact same file. |
| 6 | 2026-10-03 | Messages between host and webview use `{kind:'req'|'res'|'evt'}` envelopes rather than full JSON-RPC 2.0 | Smaller and simpler for postMessage; JSON-RPC 2.0 is reserved for the control channel (spec §6.2). |
| 7 | 2026-10-03 | `vsce package --no-dependencies` | Everything is bundled by esbuild; `igv` stays a runtime `dependency` only so `copy-igv.mjs` can verify the pin. |
| 8 | 2026-10-03 | igv alert dialogs are intercepted by replacing `browser.alert.present` | igv 3.8.9 exposes no hook; the method is public on the browser instance. The alert is forwarded to the host, shown as a VS Code warning and logged, and the dialog is suppressed. |
| 9 | 2026-10-03 | Icon is generated by `scripts/make-icon.mjs` and committed | Reproducible, dependency-free, and clearly original (spec §1.1 branding rules). |
| 10 | 2026-10-03 | `IGV_LOG_CONSOLE=1` mirrors the output channel to stdout | Lets integration tests and the agent that builds this project read logs; off by default. |
| 11 | 2026-10-03 | Integration tests are compiled by the same `esbuild.mjs` into `out-test/` and run with `@vscode/test-cli` (`.vscode-test.mjs`, tdd UI) | One build tool for everything; `tsconfig.json` includes `mocha` types for the integration files only. |
| 12 | 2026-10-03 | Viewer loci are reported exactly as igv's `currentLoci()` returns them (canonical sequence names) | Simple and truthful about what igv displays. Revisit in M1 if alias names matter to agents. |
| 13 | 2026-10-03 | Local paths travel inside configs as `{__igvVscodeLocalPath}` markers (host only) and become `{__igvVscodeFile}` broker handles before crossing to the webview | One generic deep-walk (`hydrateFileRefs`) handles references, tracks and future session configs; the webview never sees absolute paths. |
| 14 | 2026-10-03 | Webview-side chunking; the broker rejects reads above `maxChunkBytes` | Keeps the host handler stateless per request and the protocol flat. |
| 15 | 2026-10-03 | Loci reported in IGV display convention (`chr:1,234-5,678`), computed from igv's reference frames | igv's `currentLoci()` returns fractional coordinates. The spec mandates 1-based inclusive display convention for the API. |
| 16 | 2026-10-03 | Track options are an allow-list of igv keys | Typos fail with a clear message instead of being silently ignored by igv. |
| 17 | 2026-10-03 | Fixtures are generated with a project-local `.venv` (pysam, pyBigWig, numpy) instead of system samtools | No system samtools/tabix on the dev machine; pysam bundles the same functionality. |
| 18 | 2026-10-03 | `large.bam` uses random per-base qualities | Constant Q30 compressed the 600k-read BAM to 11 MB; random qualities bring it to the spec's ~60 MB target while keeping 12x depth. |
| 19 | 2026-10-03 | `igv.genomes.custom` entries are excluded from the `genomeList` passed to igv | They may carry local paths; igv only uses the list for id lookups we never trigger (we always pass a full `reference`). |
| 20 | 2026-10-04 | Custom editors use viewTypes `igv.editor` (priority default) and `igv.editorOption` (priority option) behind one provider | VS Code allows one priority per custom-editor contribution, and `igv.viewer` stays the serializer's webview-panel viewType. |
| 21 | 2026-10-04 | Custom editor loading runs detached from `resolveCustomEditor` | VS Code only starts the webview after resolve returns; awaiting our ready handshake inside it deadlocks. |
| 22 | 2026-10-04 | Restore state = key in webview state + session snapshot in workspace state | Keeps absolute paths out of the webview; entries are consumed on restore and pruned after 7 days / 20 entries. |
| 23 | 2026-10-04 | Shorthand hex colours are expanded in `validateOptions` | igv 3.8.9 throws in `darkenLighten` on `#rgb`, and the draw error rejects all concurrent track loads. |
| 24 | 2026-10-04 | Session track options = spec options merged with sanitised `track.getState()`, filtered by the option allow-list | Captures UI-made changes (height, displayMode, colour) without persisting igv internals. |
| 25 | 2026-10-04 | Opening a viewer from a data file navigates to a locus where the file has data (first BAM record / first feature), not igv's whole-genome view | Alignments are hidden in wide views; a freshly opened BAM must show reads. Agents still get igv's default unless they pass `locus`. |
| 26 | 2026-10-04 | Human add flows skip files already present in the viewer; the agent API does not | Double-click re-resolves the custom editor every time and must be idempotent; agents may legitimately want duplicates (e.g. different options). |
| 27 | 2026-10-04 | Remembered editor locus is keyed by (file, genome id) and applied with `goto` after creation | A locus from another genome passed to `createBrowser` left the viewer blank. |
| 28 | 2026-10-04 | Large-file remedies live in `LargeFilePolicy`, not in `TrackResolver`; the resolver only reports `INDEX_REQUIRED` with structured data | Keeps the resolver pure and testable; the policy owns tools, prompts and derived-dir placement. |
| 29 | 2026-10-04 | Test tool shims (`test/tools/bin`) emulate samtools/bgzip/tabix with pysam | No bioconda on the dev machine or in CI; the shims match the real CLIs' argument syntax for the subset we invoke, and real tools are used when present. |
| 30 | 2026-10-04 | `track`/`browser` lines are dropped when compressing text for tabix | Real tabix cannot skip them; igv does not need them. |
| 31 | 2026-10-04 | webviewUri mode reloads the webview and replays the session when a new resource root is needed | VS Code reloads the webview on `localResourceRoots` changes; replaying is cheaper than forbidding later additions. |
| 32 | 2026-10-04 | Remote `auto` mode decides per origin and keeps the memory in a session-wide set shared by all viewers | A CORS failure on one file predicts failures for its siblings; sharing avoids a failed direct attempt per viewer. |
| 33 | 2026-10-04 | Perf test is a gated integration test (`IGV_PERF=1`) rather than a script over the control API | The control API arrives in M4; the test writes the markdown table the spec asks for. |
| 34 | 2026-10-04 | The perf BAM has its own ~180 Mb reference at 30x rather than piling 5 GB onto the 5 Mb fixture chromosome | The first attempt (~1084x) made each 2 kb view read ~20 MB and failed every §5.4 target for reasons unrelated to the transport; a realistic depth is what the targets assume. |
| 35 | 2026-10-04 | CSP `script-src` includes `'wasm-unsafe-eval'` | igv.js's CRAM codecs are WebAssembly; without it CRAM tracks fail with a CompileError alert. Still no `'unsafe-eval'`. |
| 36 | 2026-10-04 | "IGV: New Viewer" always shows the genome picker (default first); only file opens use the default silently | A default genome made it impossible to open a viewer on another genome from the UI without changing settings. |
| 37 | 2026-10-04 | Genome mismatch check also for remote URLs, read through the proxy regardless of `igv.remote.mode` | Loading a remote track on the wrong genome produced an opaque igv error; a few KB of range requests give the same warning as for local files. |
| 38 | 2026-10-04 | `igv.tools.paths` scope is `machine-overridable` | Tool locations legitimately differ per workspace/dev container, and the dev workspace points at the test shims. |
| 39 | 2026-10-04 | Token comparison hashes both sides with SHA-256 before `timingSafeEqual` | `timingSafeEqual` requires equal lengths; hashing avoids leaking the token length and keeps the comparison constant time. |
| 40 | 2026-10-04 | `UNAUTHORIZED` added to the error codes; JSON-RPC `-32001` | The spec's list had no code for a bad token; `AGENT_DISABLED` would be misleading. |
| 41 | 2026-10-04 | CLI uses `node:util.parseArgs`, no dependencies | Keeps `dist/cli.js` small and dependency-free so it runs on the extension host's runtime everywhere. |
| 42 | 2026-10-04 | Multi-window discovery is unit-tested with two live sockets rather than two VS Code windows | Same selection code; two Electron instances in one test run would be slow and flaky. |
| 43 | 2026-10-04 | Multiple loci are sent to igv as one space-separated string | igv's `search()` and `locus` option take a string; arrays throw inside igv. |
| 44 | 2026-10-04 | Activate on `onStartupFinished` | Agents expect `igv-vscode` to work in a fresh window; the control channel and registry are created at activation. Cost is small (no webview until a viewer opens). |
| 45 | 2026-10-04 | code-server e2e uses 4.140.0 and 4.102.0 | `4.129.0` from the spike is not a published Docker tag; these are the newest plain tag and an older 4.10x. |
| 46 | 2026-10-04 | MCP server discovers the control endpoint lazily on the first tool call | `claude mcp add` starts the server before VS Code may be running; failing at startup would make the server disappear from the client. |
| 47 | 2026-10-04 | zod 3 for MCP schemas | Stable `z.record()`/`z.object()` API with SDK 1.32; the repo has no other zod user. |
| 48 | 2026-10-04 | No VS Code MCP provider registration in v1 | Optional P2 in the spec; stdio covers Claude Code and other clients. |
| 49 | 2026-10-04 | Gated Claude Code end-to-end test (`IGV_CLAUDE_E2E=1`) as the automated stand-in for human checkpoint 3 | Proves the MCP tools work for the real agent; gated because it costs Claude usage and needs a logged-in `claude`. |
| 50 | 2026-10-04 | Skill and MCP instructions include igv's base-colour legend | The agent misread a reference base colour in the first run; the legend is cheap and makes snapshot reading reliable. |
| 51 | 2026-10-04 | Release workflow drafts a GitHub Release on tag; marketplace publishing is a separate manual job | Spec §12 M6: never publish without human approval; the human wants to register a publisher later. |
| 52 | 2026-10-04 | README screenshots are the extension's own snapshots | No screen-capture tooling in this environment; they show real output and stay reproducible via the CLI. |
